OBSERVATIONS / CAVEATS
- One run per mode; tiny sample (4 files, ~10 kB). Not comparable in scale to the
  Lovable HAR (124 dependency requests, 14,287 kB).
- transferSize includes response headers; Netlify compresses JS, so
  encodedBodySize < decodedBodySize.
- In every network row, transferSize - encodedBodySize = 300 B exactly. Chrome adds a
  fixed 300 B header estimate to transferSize instead of the real header size.
  This is why the DevTools "transferred" figures are lower than the summed
  transferSize values (DevTools shows the actual, HPACK-compressed header bytes).
  Body bytes over the network (sum of encodedBodySize, network rows only):
    baseline v2: 610 + 4884 + 1576 + 1933 = 9003 B; redesign v2: 1933 B
    -> 78.5 % fewer body bytes (headers excluded).
- The encodedBodySize TOTAL on redesign-v2 (9021) also counts cached files;
  use transferSize for "bytes over the network".
- preact's transferSize/encodedBodySize differ by 19 B between baseline-v1 (5165/4865)
  and the other loads (5184/4884); decodedBodySize is identical (12093).
  Likely a different compressed variant from Netlify's edge; cause not verified.
- Netlify injected a "Powered by Netlify" badge and a script (hud?variant=public)
  into the HTML. It is not under /deps, so it is excluded from the table, but it
  means the served HTML is not byte-identical to the repo.
- "(memory cache)" vs "(disk cache)": Resource Timing reports 0 for both; the claim
  is "no network transfer", not "disk cache".
